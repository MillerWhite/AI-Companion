# Device ↔ AI Companion backend protocol

## Authentication
- HTTPS only outside local development.
- Header: `Authorization: Bearer <device_token>`.
- The token is generated by trusted server-side enrollment and stored hashed server-side.
- The device token is not the Yandex API key and must be revocable.
- Never put enrollment admin secret into HTML or firmware.

## Interpret request
`POST /api/device/interpret`

```json
{
  "utterance": "Мило, давай поиграем"
}
```

## Interpret response
```json
{
  "addressed_to_companion": true,
  "understood": true,
  "intent": "owner_invites_play",
  "action": "play",
  "emotion": "excited",
  "confidence": 0.94,
  "nonverbal_cue": "Оживиться, поднять взгляд и слегка наклониться вперёд",
  "clarification": null
}
```

## Safety and fallback
- Backend response is data, not executable instructions.
- Firmware must validate action and emotion against compile-time allowlists before applying them.
- Backend never sends sound frequencies, hardware register writes, code or arbitrary animation scripts.
- If TLS, network, auth, JSON parsing or schema validation fails, discard the cloud result and continue local behavior.
- Request body is text only. Raw audio upload is not part of this protocol.
- Device context is bounded server-side. A production release still needs owner-visible memory reset/export/deletion controls and a retention policy.
